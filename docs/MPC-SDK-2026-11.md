# MPC Plugin SDK von inMusic — Analyse

Stand: 26.11.2026
Quelle: https://github.com/inmusic-software/mpc-plugin-builder-sdk
Commit: `e78bad5` (23.11.2026), SDK 1.0, Changelog „Unreleased (1.1)“
Voraussetzung: MPC OS 3.10.1+, *Enable Enhancements* + *External Plugin Support*

## Kurzfazit

**Es gibt kein neues Plugin-Format und kein neues ABI.** Ein MPC-Plugin ist
weiterhin eine Linux-Shared-Library nach VST 2.4, die im MPC-Prozess läuft. Das
„native“ ist genau das, was QMaster, QVerb, QDelay und QDSSD schon tun. Das
Repository ist das **offizielle, MIT-lizenzierte SDK** mit Werkzeugen, Doku und
zwei neuen Zielen — kein Grund, DSP oder Framework neu zu schreiben.

Unsere Plugins sind kompatibel. QMaster wurde heute an drei Stellen an den
offiziellen Vertrag angepasst (siehe unten).

## Was neu ist

| Bereich | Änderung |
|---|---|

| Deployment | `tools/mpc_remote.py`: installieren/update/entfernen/exportieren/neu starten über SSH (Developer Mode) |
| Migration | `tools/legacy_convert.py` für Community-Pakete im alten Installer-Format |
| Host-Vertrag | präzisiert: 44,1 kHz fix, Blöcke 32–512, **in-place**, Effekte ohne MIDI, **Parameter-0-Nudge**, Chunks, Programm 0 |

Das Changelog nennt MPC Sample, Seitenhintergründe, Q-Link-Gruppen und
Validator-Checks für die kommende SDK-Version 1.1. Ein neues Laufzeitformat
steht dort nicht.

## Host-Vertrag: die Punkte, die uns betreffen

1. **Parameter 0 wird bei jedem Prepare genudged** (1.0 → zurück). Das passiert
   bei jedem Plugin ohne nativen Editor — also bei allen SDK-Plugins. Ein
   `parameterChanged(0, …)` darf nichts Teures oder Hörbares tun.
2. **Verarbeitung ist in-place.** Eingang und Ausgang teilen den Speicher.
3. **Feste 44,1 kHz**, Blöcke 32–512; die angekündigte Blockgröße ist ein
   Maximum, kleinere Werte müssen funktionieren.
4. **Effekte bekommen kein MIDI.**
5. **Programm 0 wird nach dem Laden gewählt**; der Name wird über
   `effGetProgramNameIndexed` gelesen.
6. **State ist ein Chunk**; das Framework speichert Parameter über ihre stabilen
   `id`-Strings. Parameter nach einem Release nicht umsortieren.
7. **Namen ≤ ~12 Zeichen**, Wertetext ≤ ~8; die UI ist klein.
8. **Kein Sandboxing:** ein Crash beendet die MPC.

## Stand unserer vier Plugins

| Plugin | Framework | Build | UI | MPC Sample | Parameter 0 |
|---|---|---|---|---|---|
| QMaster 1.0.2 | identisch + UI-Notify-Patch | GCC/Docker, glibc 2.32/2.35 | `gen_ui` = SDK | **ja** | gefixt |
| QVerb 1.1.1 | identisch + Patch | GCC/Docker | `gen_ui` = SDK | **ja** | Mix — harmlos |
| QDelay 1.3.5 | identisch + Patch | GCC/Docker | `gen_ui` = SDK | **ja** | Sync — harmlos |
| QDSSD 1.1.3 | identisch + Patch | GCC/Docker, glibc 2.33/2.35 | `gen_ui` = SDK | **nein, bewusst** | Bus — harmlos |

**Framework:** Der offizielle Header ist bis auf unseren Patch identisch:
`notifyHostParameterChanged()` + `requestDisplayUpdate()` nach Programm- und
Chunk-Laden. Ohne den Patch bleibt die MPC-UI auf alten Knopfpositionen — der
Fehler, den wir in allen vier Plugins behoben haben. Der Patch ist **nicht**
upstream; er sollte als PR angeboten werden.

**Build:** Unsere Docker/GCC-Builds verlangen GLIBC 2.32 (arm32) und 2.35
(arm64). Der offizielle Validator akzeptiert das (Warnschwelle > 2.36), und
MPC OS 3 hat laut SDK glibc 2.39+. Für maximale Abwärtskompatibilität und
reproduzierbare Builds ist Zig mit `…2.31` die bessere Wahl.

**UI-Tools:** `gen_ui.py` (903 Zeilen) und `make_ui_kit.py` (583) sind
**identisch** mit dem SDK. `validate.py` war älter (726 statt 831 Zeilen); für
QMaster wurde die offizielle Fassung übernommen.

## Was heute an QMaster geändert wurde

1. **Parameter-0-Falle behoben.** `Mode` liegt auf Index 0. Der Host nudged
   Parameter 0 bei jedem Prepare; unser `parameterChanged` hat dabei die
   komplette Topologie zurückgesetzt. Jetzt setzt `parameterChanged` nichts
   mehr zurück: `process()` erkennt einen **echten** Moduswechsel und ruft
   `resetTopology()`. Der Nudge bleibt damit folgenlos, echte Wechsel resetten
   weiterhin.
2. **MPC-Sample-Knob-FX-Zuordnung** in `plugin.json`:
   - Knobs: Clip (3), Trim (1), Ceiling (5)
   - SHIFT: Release (6), Mono (7), Tilt (2)
   - `shortName`: „QMaster“
   - Mode bleibt auf Programm 0 (Master); auf dem MPC Sample ist der Screen
     ohnehin nicht da.
3. **Offizieller Validator** übernommen. Ergebnis:
   `0 errors, 0 warnings`, inklusive der Knob-Zuordnung.

Der neue Build liegt als Paket vor; die Installation auf der MPC steht noch
aus, weil das Laufwerk nicht angeschlossen war.

## Risiken und offene Punkte

- **MPC Sample:** QMaster ist ein Master-/Bus-Prozessor. Auf dem MPC Sample
  wirkt er als Insert-/Input-Knob-FX, nicht als Master. Ob das klanglich sinnvoll
  ist, muss man hören. QVerb/QDelay sind naheliegender; QDSSD braucht zwei
  Plugins und einen Shared-Memory-Bus — auf dem Sample unklar.
- **Programm 0 ist auf dem MPC Sample entscheidend:** Nicht zugeordnete
  Parameter bleiben auf Programm-0-Werten. Bei QMaster ist das „Init“ (Clip 0,
  Trim 0, Ceiling −1). Wer dort mehr Loudness will, muss die Knobs drehen.
- **Zig-Umstellung** ändert die glibc-Anforderung und die Codegenerierung
  (Clang/libc++ statt GCC/libstdc++). Vor dem Release auf beiden MPC-Familien
  testen.
- **Netzwerk-Deployment** braucht Developer Mode (SSH). Unser MPC war zuletzt
  unter `192.168.0.70` nicht erreichbar; USB bleibt der sichere Weg.
- **Kein Sandboxing** — der Host-Vertrag sagt es ausdrücklich. Die
  Host-Simulator-Tests bleiben Pflicht.

## Befehle

```bash
# SDK holen
git clone https://github.com/inmusic-software/mpc-plugin-builder-sdk

# Offizieller Build (SDK-Layout)
python tools/build.py plugins/<Name>

# Offizieller Validator auf unser Paket
python /pfad/zum/sdk/tools/validate.py \
  "dist/mpc/r3d0xStyle - VST - QMaster" --params params.json

# Netzwerk-Deployment (Developer Mode + SSH)
python3 tools/mpc_remote.py <MPC-IP> doctor
python3 tools/mpc_remote.py <MPC-IP> add "dist/mpc/r3d0xStyle - VST - QMaster"
```

## Entscheidung nach Gegenprüfung (26.11.2026)

Eine unabhängige Gegenposition hat P1–P3 geprüft. Ergebnis:

### P1 — begrenzt umgesetzt

- **QVerb 1.1.1:** Knob-FX-Mapping (Mix/Decay/Tone, SHIFT PreDly/Width/Clear),
  Label `PreDly` wegen 8-Zeichen-Grenze.
- **QDelay 1.3.5:** Mapping Div L/Feedback/Mix, SHIFT Sync/Low Cut/High Cut.
  Time ist auf dem Sample nicht exponiert; das wäre bei Sync-On wirkungslos.
  Lizenz in `plugin.json` von MIT auf GPL-3.0-or-later korrigiert (passt zur
  LICENSE-Datei).
- **QDSSD + SC Input: kein Mapping.** Ohne SC Input ist QDSSD ein No-op;
  der Zwei-Plug-in-Bus ist auf dem MPC Sample nicht dokumentiert. Ein Bus-Knopf
  ohne Sender wäre schlimmer als der generische Fallback.
- **QMaster 1.0.1:** Mapping und Parameter-0-Fix bleiben.
- Validator: offizielle Fassung wird für die Prüfung benutzt, aber nicht in alle
  vier Repos kopiert (eine Kopie in QMaster genügt).

### P2 — verschoben

Zig 0.17.1 canary: arm32/arm64 bauen, GLIBC 2.27, Validator 0 Fehler. Aber:

- arm32 wächst von 86 KB auf 207 KB (2,4×), arm64 von 195 KB auf 256 KB.
- libc++ statt libstdc++, andere ARM-Attribute; Host-Sim-WAVs nicht bitidentisch.
- Aktuelle Builds verlangen 2.32/2.35; der offizielle Validator akzeptiert das
  (Warnschwelle > 2.36), MPC OS 3 hat glibc 2.39+. Kein bekannter Vorteil für
  unterstützte Geräte.
- Ohne Hardware-Nulltest kein Shipping-Wechsel. Die Zig-Kommandos bleiben als
  Canary dokumentiert.

### P3 — nicht umstrukturiert

- `validate.py`, `gen_ui.py`, `package.py` und `mpc_remote.py` sind eigenständig
  und laufen auch auf unseren `dist/mpc`-Ordnern.
- `build.py` würde unser lokales Framework (inkl. UI-Notify-Patch) ignorieren,
  QDSSD nicht als zwei Binaries bauen und bei QDelay den JUCE-Baum erwischen.
- `mpc_remote.py` braucht Developer Mode/SSH; die MPC war nicht erreichbar.
- Upstream: erst ein Issue mit Minimal-Repro, kein PR. Der Patch ruft
  `audioMasterAutomate` in `effSetChunk`/`effSetProgram` auf; das ist
  reentrancy-empfindlich. Patch liegt in `docs/upstream/`.
